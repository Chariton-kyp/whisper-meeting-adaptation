# Far-field meeting ASR: what LoRA adaptation of Whisper gains, and what it costs

> **Status: experiment running.** The design was pre-registered before any adaptation run
> ([`docs/design.md`](docs/design.md)). Every number in this README comes from a file in
> [`results/`](results/) produced by the scripts in this repository. Results that are not available
> yet are marked _pending_.

## Question

Fine-tuning Whisper on the AMI meeting corpus is well studied for close-talk microphones (IHM). This
study looks at the harder, product-relevant condition: a **single distant microphone (SDM)**. It asks
four questions:

1. **Gain.** How much does LoRA adaptation of `whisper-large-v3-turbo` on AMI SDM reduce WER on
   held-out meetings, both far-field and close-talk?
2. **Where the gain lives.** A matched-budget ablation compares LoRA on the encoder only, the
   decoder only, and both. The encoder carries acoustic adaptation; the decoder carries language
   and transcription style.
3. **What the gain consists of.** AMI references are verbatim (repetitions, fillers). A
   disfluency-insensitive WER, with its rule fixed in advance, separates style adaptation from
   better recognition of content.
4. **What it costs.** Formatting (casing and punctuation), out-of-domain accuracy (Earnings-22),
   hallucinations on short and filler-only segments, and compute.

## Setup

| | |
|---|---|
| Data | AMI Meeting Corpus, Full-corpus-ASR partition (`edinburghcstr/ami` @ `46f28f2`). Train has 135 meetings and 76.9 h; validation 18 meetings and 8.9 h; test 16 meetings and 8.7 h. Train and test share **no meetings and no speakers** ([`splits/README.md`](splits/README.md)). |
| Paired conditions | The IHM and SDM test sets contain the same 12,643 segments with identical references, so the acoustic condition can be compared utterance by utterance. |
| Model | `openai/whisper-large-v3-turbo` (809M). LoRA r=32 on every attention and MLP projection of the adapted part. 16,000 SDM training utterances, 1,000 steps, identical across arms. |
| Decoding | Greedy, no timestamps, the same for every system. No decoding tuning. |
| Metric | Corpus-level WER after Whisper's English normalizer, with 95% CIs from a meeting-level cluster bootstrap. Utterances from the same meeting are not independent, so the bootstrap resamples whole meetings. System comparisons use a paired bootstrap on identical utterances. |
| Hardware | One laptop GPU (RTX 4080 Laptop, 12 GB). Peak training memory is 7.5 GB. |

## Findings from building the harness

These are reported because each one would otherwise have silently biased the results:

- **Normalizer artifact.** Whisper's English normalizer leaves a bare "." from a trailing ellipsis,
  and the "." is scored as an insertion. It affects 575 of the 13,098 zero-shot SDM validation
  hypotheses and no references. Models adapted on unpunctuated labels stop producing ellipses, so the
  artifact would have inflated the measured benefit of adaptation. It is fixed for all systems
  ([amendment 3](docs/design.md#amendments)).
- **Hallucinations on filler-only segments.** 891 validation segments contain only fillers ("UH",
  "UM"), so their reference is empty after normalization. Zero-shot turbo often produces text for
  them, most commonly "Thank you." This is tracked as a separate cost (insertions on empty
  references). Numbers: _pending_.
- **Silent memory spill on Windows.** Above physical VRAM, the WDDM driver spills to system RAM
  without raising an error. In one run, `whisper-small.en` at batch 16 peaked at 16.5 GB on a
  12.9 GB card and took 37.3 s/step. With gradient checkpointing actually active, the same model
  and batch peaked at 4.1 GB and took 1.48 s/step, 25× faster. Note that `from_pretrained` returns a
  model in eval mode, and Hugging Face gradient checkpointing only runs in train mode. Training runs
  record `spilled_to_sysmem`. Source: [`results/smoke/`](results/smoke/).

## Reproduce

```bash
uv sync                                        # Python 3.12, torch 2.14 (CUDA 13.0)
uv run pytest                                  # metric, normalizer and overlap unit tests
uv run python scripts/make_splits.py           # regenerates splits/ (seeded)
bash scripts/run_all.sh                        # validation, 3 training arms, all evaluations
uv run python scripts/analyze.py --name sdm_test --runs results/zeroshot_sdm_test results/both_sdm_test \
    results/encoder_sdm_test results/decoder_sdm_test
```

## Limitations

- **"Zero-shot" means not adapted by us.** Whisper's pre-training data is undisclosed and was not
  de-duplicated against AMI.
- **Evaluation scope.** Segmented utterances only: no long-form transcription, speaker attribution
  or streaming.
- **Statistical power.** One seed per arm and 16 test meetings, so the confidence intervals are wide.
- **Normalization.** The Whisper normalizer does not unify some AMI spelling conventions
  ("okay"/"ok", "cause"/"because"). Their effect is analysed separately, and labelled post hoc.
